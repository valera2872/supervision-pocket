# Supervision Pocket — alpha 0.9.3

Android-приложение для психологов и супервизоров: короткая профессиональная рефлексия после консультации, подготовка кейса, передача выбранного запроса, повестка супервизионной встречи, структурированный итог и проверка результата.

## Что реализовано

### Для психолога, проходящего супервизию

- отдельный вход по роли «Я психолог»;
- полностью локальный запуск без регистрации;
- правила обезличивания клиентских данных;
- PIN 4–6 цифр и блокировка при уходе приложения в background;
- AES-256-GCM-шифрование локального хранилища;
- обезличенные карточки случаев;
- голосовой ввод через системную службу распознавания речи;
- приложение не сохраняет аудиофайлы;
- два режима записи:
  - «Быстро» — эпизод, интерпретация, реакция, действие, затруднение и вопрос;
  - «Подготовить кейс» — запрос клиента, релевантный контекст, текущая динамика, рабочая гипотеза, предпринятые действия, ресурсы, этический контекст и тип запроса;
- явное разделение наблюдаемых фактов, интерпретаций и реакций специалиста;
- автоматическое сохранение черновика;
- редактирование и удаление отдельных записей;
- удаление конкретного случая;
- профессиональная хронология по случаю;
- ручная передача выбранного запроса как текста или зашифрованного пакета `.sprequest`;
- расширенный пакет сохраняет поля подготовленного кейса;
- архивирование завершённых случаев.

### Для супервизора

- отдельное рабочее пространство с навигацией «Сегодня / Супервизанты / Встречи»;
- полная профессиональная карточка супервизанта;
- статусы запросов: новый, в повестке, разобран, требует продолжения, отложен;
- планирование встречи и формирование повестки;
- подготовка каждого запроса по семи фокусам:
  - клиент;
  - интервенции;
  - терапевтические отношения;
  - состояние психолога;
  - отношения в супервизии;
  - впечатления супервизора;
  - широкий контекст;
- выбор рабочей роли супервизора: фасилитатор, консультант, учитель или эксперт;
- фиксация недостающей информации, вопросов и этического/системного контекста;
- личная заметка супервизора, не предназначенная для передачи;
- структурированный итог встречи:
  - что стало яснее;
  - рассмотренные перспективы;
  - рабочая гипотеза;
  - оставшаяся неопределённость;
  - следующий профессиональный шаг;
  - маркер наблюдения;
  - вопрос для продолжения;
  - короткий общий итог;
- проверка результата после завершённой встречи;
- завершение и повторное открытие встречи;
- история завершённых встреч;
- отдельное зашифрованное хранилище кабинета супервизора.

## Методологическая основа 0.9.3

Версия строит процесс вокруг полного цикла:

`эпизод → рефлексия → запрос → подготовка супервизора → встреча → рабочий шаг → проверка результата`.

Модель данных подготовлена для разных супервизионных подходов и не превращает одну школу в обязательный алгоритм. Фокусы и роли служат навигацией внимания, а не автоматическим заключением.

## Совместимость данных

Формат 0.9.3 обратно совместим с локальными данными 0.8.x–0.9.2. Старые записи открываются в быстром режиме; новые поля получают безопасные пустые значения. Старые встречи сохраняют прежние итоги и получают пустые структурированные разделы.

## Конфиденциальность голосового ввода

Распознавание выполняет системная служба телефона. В зависимости от устройства обработка может происходить локально или сервисом распознавания. Пользователь получает предупреждение не называть имена, адреса, школы и другие идентифицирующие сведения. Само приложение хранит только полученный текст и не сохраняет аудиозапись.

## Запуск

1. Установить актуальный стабильный Flutter SDK и Android SDK.
2. Один раз дополнить сгенерированные platform-файлы:
   `flutter create --platforms=android --org com.supervisionpocket --project-name supervision_pocket .`
3. Выполнить `flutter pub get`.
4. Проверить `dart format`, `flutter analyze` и `flutter test`.
5. Собрать: `flutter build apk --debug`.

## GitHub Actions

Workflow `.github/workflows/flutter-ci.yml` при каждом push в `main`/`develop` и при каждом pull request:

- устанавливает stable Flutter и Java 17;
- добавляет стандартные сгенерированные Android-файлы;
- проверяет форматирование и анализатор;
- запускает тесты;
- собирает debug APK;
- сохраняет APK как artifact запуска workflow на 14 дней.

## Подпись альфа-сборок

Debug APK использует тестовый ключ, сохраняемый в закрытом кэше GitHub Actions. Это позволяет устанавливать новые альфа-сборки поверх предыдущих сборок с той же подписью без потери локальных данных. Перед публикацией потребуется отдельный закрытый release/upload key.
